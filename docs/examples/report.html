SUDO-DEF-004 Policy Default

Dangerous Environment Variables Preserved (env_keep)

CRITICAL
Source Line (docs/examples/policy/sudoers:3)
Defaults env_keep += "LD_PRELOAD HTTP_PROXY"
Source: Sudoers Policy
Location:

The policy explicitly preserves dangerous environment variables: LD_PRELOAD. This can allow local users to alter runtime linker behavior, interpreter module paths, or pager/editor execution in elevated processes.

Remediation

Remove dynamic library path, interpreter path, and shell/editor environment variables from 'env_keep' and 'env_check', and keep them in 'env_delete' in sudoers Defaults.

Example Sudoers Configuration (visudo) 
Defaults env_keep -= "LD_PRELOAD"

Creating a Group Dedicated to the Use of sudo

0 Violations — Compliant
Verbatim Standard Requirement
R38 - Creating a group dedicated to the use of sudo: A group dedicated to the use of sudo must be created. Only the members of this group should have the right to run sudo. Example: # ls -al /usr/bin/sudo → -rwsr-x---. 2 root sudogrp [...] /usr/bin/sudo. Warning: this modification can be overwritten by an update of the sudo package; it is recommended to check the access rights of the file after an update and apply them again if needed.
Traduction française (ANSSI BP-028) : R38 - Créer un groupe dédié à l'utilisation de sudo : Un groupe dédié à l'utilisation de sudo doit être créé. Seuls les membres de ce groupe doivent avoir le droit d'exécuter sudo. Exemple : # ls -al /usr/bin/sudo → -rwsr-x---. 2 root sudogrp [...] /usr/bin/sudo.

Security Rationale: sudo is a setuid root executable installed by default with open execution rights. Restricting execution to a dedicated group reduces the attack surface when the system or the binary itself is affected by exploitable vulnerabilities (e.g. CVE-2019-14287, CVE-2021-3156). A sudo binary that is writable by group or other, or not owned by root, defeats this restriction and allows immediate local root compromise.

sudo chmod 4755 /usr/bin/sudo

sudo chown root:sudogrp /usr/bin/sudo
sudo chmod 4750 /usr/bin/sudo

Sudo Configuration Guidelines

5 Violations (MEDIUM)
Verbatim Standard Requirement
R39 - Sudo configuration guidelines: The following guidelines must be enabled by default: noexec (applies the NOEXEC tag by default on the commands); requiretty (requires the user to have a tty login); use_pty (uses a pseudo-tty when a command is executed); umask=0077 (forces umask to a more restrictive mask); ignore_dot (ignores the "." in $PATH); env_reset (resets the environment variables). Guidelines for the /etc/sudoers configuration file: Defaults noexec,requiretty,use_pty,umask=0077 / Defaults ignore_dot,env_reset. It is then possible to override a default value if needed when an entry is added for a user or for a group (e.g. myuser ALL = EXEC: /usr/bin/mycommand).
Traduction française (ANSSI BP-028) : R39 - Recommandations de configuration pour sudo : Les directives suivantes doivent être activées par défaut : noexec (applique par défaut la balise NOEXEC aux commandes) ; requiretty (exige que l'utilisateur dispose d'un tty) ; use_pty (utilise un pseudo-tty lors de l'exécution d'une commande) ; umask=0077 (force un umask plus restrictif) ; ignore_dot (ignore le « . » dans $PATH) ; env_reset (réinitialise les variables d'environnement). Without umask=0077, files created by root inherit the caller's permissive umask.

0 Violations — Compliant
Verbatim Standard Requirement
R42 - Banishing the negations in sudo policies: Policies applied by sudo through the sudoers file should not involve any negation. 3 Violations (HIGH)
Verbatim Standard Requirement
R43 - Defining the arguments in sudo specifications: All commands in the sudoers configuration file must strictly specify the arguments allowed to be used for a given user.
